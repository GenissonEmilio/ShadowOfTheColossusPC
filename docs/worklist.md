| 7 | `modelDispHook` cost | done (not committed) | Throttled attract demo (frames 1000-1400): 92.5 -> 81.5 ms a frame (game 68 -> 68.5, hooks 14.2 -> 3.2, render 9.8 -> 9.8); unthrottled 30 -> 25 ms (game 21.5 -> 20.7, hooks 5.4 -> 1.1, render 3.0 -> 3.3). | 8 | Render thread | done (not committed); cap at 30 stays off | The GL / Vita renderer draws and shows each frame on a thread of its own (`GlBackend`, native_renderer_gl.cpp): the game thread records the next frame (draws, the frame's vertex / index arena, skin palettes, effects, uploads) apart from the one being drawn, and `endFrame` swaps the two and goes on; it waits only while the frame before is still being drawn (one frame in flight). Every GL call is the render thread's: mesh / skinned / texture uploads are copied and queued, applied before the frame's draws; `hasMesh` / `hasTexture` answer from the game thread's own lists; eviction of kept meshes and textures happens at a hand-over (the frame handed over keeps what it draws or uploads), their GL objects deleted on the render thread. The present (the host's swap, with the FPS overlay and the player menu, `drawHostFrame` from the native present hook) is on the render thread too. Vita: render thread on core 2 (`sceKernelChangeThreadCpuAffinityMask`, 512 KB stack), game thread on cores 0-1. macOS GL: the context is the render thread's (built there). Switch: Debug "Render thread", `SOTC_RENDER_THREAD=0/1` (on by default on the Vita, off on the Mac: off, `endFrame` waits for its frame). Frame log: render / present are the render thread's (last frame drawn), `wait` the game thread's wait. Waits re-check every 2 ms: in Vita3K a wake-up of the newlib pthread condition got lost (with one condition for both ways the game thread waited on an idle render thread for good, in 3 of 3 throttled cap-30 boots; none in the runs since). Throttled attract demo (frames 1100-1460): 81.5 -> 71.3-72.1 ms a frame (game 68.2-68.8, hooks 3.1, render 8.7 on its own thread, wait 0); unthrottled 25 -> 22.0-22.8 ms (44-45 fps; render 3.0). Same build with the switch off: 79.2-80.9 ms throttled (wait 9 = render + present). Cap at 30 (`SOTC_CAP30=1`, throttled): still holds the whole EE when the game is a frame ahead (now waiting for the render thread's swap instead of doing it), so the guest loader starves: the boot's "Loading data" screen took ~170 s at a steady 30 fps instead of a few seconds (the old code: still on it after 150 s). Left off; to have it, a frame the render thread cannot take yet would have to be dropped (its uploads kept) instead of waited for. Mac GL (`SOTC_NATIVE_GL=1`, `SOTC_RENDER_THREAD=1`) route to the plain: pictures as the old code's (the letterbox fades a few snapshots later, the route's timing), the memory card menu, render 7-11 ms off the 16.6 ms game frame, no wait; off works too.
